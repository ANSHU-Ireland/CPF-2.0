- **CPF-46** ✅ Session & authz hardening — migration 0010 adds `auth_sessions.absolute_expires_at` (hard 24h cap from login, set explicitly in the login INSERT) and `auth_sessions.stepped_up_at` (marks the most recent full re-authentication). `requireAuth()` (`modules/auth/guards.ts`) now performs sliding renewal on every authenticated request — `expires_at = LEAST(now() + 12h, absolute_expires_at)` — so activity keeps a session alive but it can never outlive the 24h absolute cap regardless of how active the caller is. New `DELETE /v1/orgs/:orgId/users/:userId/roles/:role` admin endpoint (`platform/routes.ts`) removes an `org_memberships` row and, per the simplest-safe mitigation for mid-session capability changes, revokes ALL of the affected user's active sessions (rather than attempting to surgically downgrade a live session) — audited as `org.role_removed` with the revoked-session count, and refuses (409 `LAST_ORG_ADMIN`) to remove an organisation's last `org_admin` so an org can never lock itself out. New step-up authentication mechanism: `POST /v1/auth/step-up` (`auth/routes.ts`) re-verifies the caller's password (plus TOTP if MFA-enrolled) and marks the *current* session as freshly authenticated (`stepped_up_at = now()`) without issuing a new bearer token; a new `requireFreshAuth` guard composes after `requireOrgRole` in a route's `preHandler` array and returns 401 `STEP_UP_REQUIRED` if the session's `stepped_up_at` is older than `STEP_UP_FRESHNESS_MINUTES` (5). Applied to a new org data-export endpoint, `GET /v1/orgs/:orgId/export` (`org/views.ts`) — an admin-only, audited (`org.data_exported`, counts only) bulk JSON export of the org's candidates/sessions/reviews, the first such export capability in the codebase. Web-side re-prompt UI for `STEP_UP_REQUIRED` was **not** built this step (no export/report UI surface currently calls this endpoint) — noted honestly as scoped-out; the API contract is stable and ready for a future UI to consume. Integration-tested: fresh login exports immediately; an artificially-aged `stepped_up_at` triggers 401 `STEP_UP_REQUIRED`; a failed step-up attempt (wrong password) returns 401 `STEP_UP_FAILED`; a successful step-up re-verification restores export access; role removal immediately invalidates the affected user's session (`/v1/auth/me` → 401) and is idempotent-safe (repeat removal → 404); removing an organisation's sole remaining `org_admin` is rejected with 409; sliding renewal is verified to clamp `expires_at` to an artificially-close `absolute_expires_at` rather than extending a fresh 12h window.
